# 架构与验收边界

`cli → runner(flock) → autopilot/任务领取 → routing 或 brain_jobs → SQLite + 本地证据`。

- `autopilot.py`：持久化 researching/reviewing/simulating/closed；单活跃轮次，阶段变更与新任务在事务中保存。
- `routing.py`：首次领取冻结预设，隔离输入副本、按次保留输出、预算与期限门禁、有限重试、容量故障回落。
- `wrappers/agent.py`：关闭 stdin、进程组超时、文件锁、产物校验和 CLI 终态校验。
- `research_dsl.py`：只接收三个抽象角色和有限操作符的 AST，本地编译，禁止模型输出任意平台代码。
- `research_gate.py` / `evidence_gate.py`：绑定审查文件、声明和请求摘要；声明形式完整不能证明来源真实。
- `brain_client.py` / `brain_jobs.py`：限定官方 origin、不跟重定向；先写 POST 意图、只 POST 一次、GET 可恢复、真实结果核验入账；没有提交接口。
- `store.py` / `db.py`：WAL、外键、事务领取、尝试记录和恢复。
- `importer.py` / `dedup.py`：synthetic 与真实分流，候选/请求去重。`report.py` / `usage.py` / `task_view.py`：中文状态和计量，未知成本不写零。

## 数据边界

模型只获得通用金融概念和历史模型提案；平台字段映射、cookie、目录文件、回测结果、PnL 保留本地。配置中的实盘字段和证据哈希不进入 Git。`chmod 0700` 和 cwd 本身不是隔离；生成的 macOS sandbox 才阻止模型进程访问项目、私有目录、Downloads 和 Chrome profile，并限制写路径。

该 sandbox 是特定路径隔离，仍允许网络和其他未拒绝的读取，不能宣称整台 Mac 或全部供应商凭证被完全隔离。CLI 必须可信；更强隔离需独立用户/VM。任意新增 Provider 不自动获得安全认证。不要把含密钥的环境变量或未筛选输入交给模型。

不同渠道的审查提供一次否决机会，不等于独立专家或不同底层模型。结构指纹会保守合并不同数学表达式，也不能证明经济机制原创。研究范围有限，重复提案可能被持续拒绝；应根据归档结果人工评估是否扩大有证据支撑的范围。

## 验收层次

1. 源码与离线故障测试：验证状态机、门禁和恢复，不证明平台权限。
2. CLI 真实终态与产物：验证调用完成，不证明结论正确。
3. BRAIN 真实回执、结果比对和入账：证明真实回测完成，不证明研究有效。
4. 样本外、交易成本、时点与幸存者偏差验证：属于后续研究验收，当前不自动授予。
5. 平台提交、最终有效、报酬资格、现金到账：分别记录，不能互相代替。

原始首次财报机制研究所需的 first-reported、可用时点、历史成员和退市等证据仍未齐。本机已经跑通的平台内探索不替代该研究协议的验收。没有经过长期稳定性观察、整机灾难恢复演练或独立安全审计，不能声称零缺陷或最优。
